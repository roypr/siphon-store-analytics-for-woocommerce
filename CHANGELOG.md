# Changelog

All notable changes to Siphon Store Analytics for WooCommerce will be documented in this file.

## [3.3.0] — Nov 2026

- **Identity change** — Plugin identity changed from Store Insights for WooCommerce to Siphon Store Analytics for WooCommerce

### Added
- **WordPress AI Client backend (default on WordPress 7.0+).** Insight generation can now go through `wp_ai_client_prompt()`, so WordPress routes the request to whichever provider the site owner connected under Settings → Connectors. On this path the plugin stores no API key of its own. Implemented in `includes/class-ai-service-core.php` (`SILC_WIA_AI_Service_Core`), guarded by `function_exists()` + `wp_supports_ai()` so nothing core-specific is called on WordPress 6.5–6.x.
- **Backend selector** in the Settings panel (Automatic / WordPress AI Client / Your own API key), persisted as the `silc_wia_ai_backend` option and routed by `includes/class-ai-service.php` (`SILC_WIA_AI_Service`). Automatic resolves to the WordPress AI Client when available and to BYOK otherwise; an explicit BYOK choice always wins, and a saved `core` choice degrades to BYOK rather than failing when AI is unavailable.
- Backend status in the dashboard: the top bar names "WordPress AI Client" when the core path is active (it shows the model id for BYOK), and a notice appears when the WordPress AI Client is selected but no connector is set up yet.
- **Model preference works on both backends.** The Model field is shown for the WordPress AI Client too and is passed to `using_model_preference()`. It is a preference, not a requirement: when the connected provider does not offer that id, WordPress picks one itself instead of failing. An empty value now means "no preference" on that path, while BYOK keeps its "fill in the provider default" behaviour. The preference is read as stored (`SILC_WIA_API::get_model_preference()`), because the BYOK model normalisation would otherwise discard an id that belongs to a different connector.
- **Temperature is now a choice, not a guess.** A new `temperature_mode` setting (`Automatic` / `Always` / `Never`) decides whether the value is sent at all. `Automatic` keeps the existing behaviour for BYOK (send only to models known to accept it) and sends nothing through the WordPress AI Client — requesting a temperature there removes every model that does not advertise support for it, which is all current OpenAI reasoning models. It is set on the Advanced section of the Settings panel next to the temperature value.
- **Reasoning effort setting.** A new `reasoning_effort` setting (`Provider default` / `none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`) is sent as `reasoning: { effort: … }` through the WordPress AI Client (the shape the OpenAI Responses API expects) and as `reasoning_effort` with your own API key. It is never sent to Claude endpoints, which manage extended thinking themselves. The list is the union of the levels providers document rather than a per-model map.
- **Mistyped settings no longer break an insight.** If a provider rejects the requested temperature or reasoning level, the request is retried with the offending parameter removed (core: up to two simpler attempts; BYOK: up to two adapted retries). The connection test reports which setting had to be left out, and provider errors carry a tip pointing at Temperature, Reasoning effort and Model.

### Changed
- Bring-your-own-key (BYOK) is **kept as a first-class fallback**, not removed. It remains the only path on WordPress before 7.0, for self-hosted/custom endpoints (Ollama, LocalAI, vLLM, LM Studio, gateways), and when AI is disabled site-wide (`WP_AI_SUPPORT` / the `wp_supports_ai` filter).
- Both backends build their prompts with the same functions (`SILC_WIA_API::build_insight_system_prompt()` and `build_insight_user_prompt()`, now public) and reuse `SILC_WIA_API::parse_insight_json()`, so prompt and parsing behaviour cannot drift between them. The core path repeats the one-shot "your previous response was not valid JSON" correction attempt.
- `using_max_tokens()` is set to at least 2000 tokens on the core path (raised from the stored Max Tokens setting) so the JSON answer is not truncated; the shared floor lives in `SILC_WIA_API::get_insight_max_tokens()`.
- The insight cache key now includes the active backend (`core`, or `byok|api_url|model`), the model preference, the temperature mode/value and the reasoning effort, so changing any of them cannot serve an answer generated by the previous configuration.
- The connection test probes whichever backend is active: a 20-token text request through the WordPress AI Client (which names the model that actually answered), or the existing endpoint + key call.
- The "always send temperature" fallback in `SILC_WIA_Provider_Adapter::adapt_rejected_body()` now also drops a rejected `reasoning_effort`, and `SILC_WIA_API::send_request()` retries up to twice so temperature and reasoning effort can both be dropped in one request.
- Chart.js upgraded from 4.4.7 to 4.6.1 (`assets/lib/chart.min.js`), and the enqueue version with it. Every chart type the plugin produces was re-tested against the new build: bar, line, pie, doughnut, horizontalBar, radar and polarArea.

### Fixed
- Settings saved a temperature of `0` and a Cache Duration of `0` ("off") as the default value, because the dashboard used `value || default`. Both fields now treat `0` as a real value.
- Horizontal bar charts render horizontally again. Chart.js 3 removed the `horizontalBar` type, so it is now a `bar` chart with `indexAxis: 'y'`, the value axis starts at zero, and the axis titles follow the orientation. This affected the built-in "Top 5 products by quantity sold" Library item and any AI-generated horizontal chart.
- Radar and polar area charts no longer draw two stray cartesian x/y axes behind the chart. They use a single radial (`r`) scale, styled like the rest of the dashboard.
- Single-value answers are no longer priced by mistake. Currency detection in `includes/class-insight-renderer.php` now treats only explicit money words (`revenue`, `amount`, `order_total`, …) as prices, so a count like "total customers" renders as `1,234` instead of `$1,234.00`. Column names from the executed SQL are preferred over question wording, count columns (`total_customers`, `order_count`) always win, and bare plurals (`sales`, `refunds`) are left to the question. Currency formatting can still be missed in a few phrasings; that is intentional.

### Docs
- The **External services** section in `readme.txt` and `README.md` now covers both backends: which service receives the request (the WordPress AI Client and its Connectors, or the provider you configured), what is sent on each request, when it is sent, and that each connector/provider publishes its own terms-of-service and privacy-policy links.
- Suggested privacy-policy text covers the WordPress AI Client path (no plugin-stored key, connector governs the request) alongside the direct-provider path.
- New FAQ entries explain the two AI backends and why the WordPress AI Client can be unavailable on a given site. Installation steps, the FAQ reference to the admin notice and the "Source code" URL now use the new folder name, menu name and repository.
- Plugin header description and readme requirements now mention the WordPress AI Client.

### Admin notices (Guideline 11)
- The "WooCommerce is required" notice is now scoped to the Plugins screen instead of appearing on every admin page. The plugin ships no promotional, upgrade or dashboard-wide notices.

### Removed on uninstall
- The saved backend choice (`silc_wia_ai_backend`) is deleted together with the other options.

## [3.2.1] — Nov 2026

### Security
- Insight history no longer stores result rows. Entries keep the question, the SQL and the pre-render display config, so a past insight is re-run against the live database when opened (same path as a Library item) instead of reading a stored copy that could contain customer names, emails and addresses. Entries saved by earlier versions are trimmed on upgrade.
- The settings option (which holds the API key) and the history option are written without `autoload`, so they are no longer loaded into memory on every front-end, REST and cron request, nor captured in options caches and backups.
- Plain-HTTP API URLs are refused: the key and the prompt only travel over HTTPS, except for local endpoints (localhost, private/reserved IPs, `.local`, `.test`, single-label host names). Enforced when saving and again when a request is built, so a URL stored by an older version cannot leak the key.
- Uninstalling now also deletes the cached insight transients (payload + timeout rows) and the legacy `silc_wia_query_history` option, instead of leaving rendered answers in the database.
- The insight cache key includes the endpoint and model, so switching provider or model cannot serve a cached answer generated by the previous configuration.
- Every AJAX input is type-checked before it is used. `settings`, `result_json`, `sql`, `chart_config` and `list_config` must be strings (and the two configs must decode to objects), the insight `type` is whitelisted, and stored result payloads are normalized before rendering. A hand-written request such as `settings[]=…` or `{"chart_config":"x"}` previously reached `json_decode()`/`trim()`/a typed renderer argument with the wrong type and produced a PHP fatal instead of a JSON error.

### Fixed
- The Max Tokens setting now drives the request budget again (the 3.1.0 entry claimed this, but the budget was still the `INSIGHT_MAX_TOKENS` constant). Values below 800 are raised to 800 so the JSON reply is not truncated; the default is 1500.
- Refreshing a chart re-rendered it with the post-render config (the AI's chart type and transform were lost). The response now carries the pre-render `render_config`, which the Refresh button uses.

### Docs
- Privacy policy text and readme now describe what is kept locally (question, SQL, display config, temporary cached answer), the HTTPS requirement, and the blocked credential columns.

## [3.2.0] — Nov 2026

### Security
- Credential columns are no longer exposed: `user_pass`, `user_activation_key`, `post_password` and session-token meta (`session_tokens`) are stripped from the schema sent to the AI, from the schema REST payload, and from the prompt, and the SQL validator now rejects any query that names them — including `wp_usermeta` lookups that target the session meta key as a value.
- The SQL validator now strips string literals with escape handling before the forbidden-keyword scan, so a legitimate value such as `CONCAT('Coupon #', id)` is no longer mistaken for a comment marker or keyword, while stacked statements and comment/hex payloads are still rejected.
- Changing the API URL no longer silently reuses the previously stored API key. A key is provider-specific, so saving a different endpoint without entering a new key clears it and the settings screen explains why.

### Changed
- New `SILC_WIA_Provider_Adapter` owns the provider registry (endpoint, default model, wire format, completion-limit parameter, key hints). The settings screen reads it from the server instead of carrying its own copy.
- The settings screen now selects a provider (OpenAI, Claude, OpenRouter, DeepSeek, Groq, Mistral, xAI, Custom) and fills the endpoint; Custom keeps the free-text URL field for Azure, Ollama, LocalAI, vLLM, LM Studio and any other compatible gateway.
- The completion-limit parameter is chosen per provider instead of guessed from the model name: OpenAI, OpenRouter and Groq send `max_completion_tokens`; Anthropic, DeepSeek, Mistral and xAI send `max_tokens`. If an endpoint rejects the choice, the request is retried once with the other name (temperature is dropped when the error blames it).
- Claude is supported natively: requests go to `/v1/messages` with `x-api-key` and `anthropic-version`, the system prompt is hoisted out of `messages`, response content blocks are mapped back to the OpenAI envelope, and extended thinking is requested only where the model accepts it.
- Default model ids refreshed per provider, and a stored model that cannot belong to the configured endpoint (for example a GPT id after switching to Claude) is replaced with that provider's default instead of being sent.
- The Test Connection button now goes through the same provider-aware request path as a real insight.

### Removed
- The "Function whitelist" claim in `README.md`, which did not match the validator (it blocklists, it does not whitelist functions).

## [3.1.0] — Nov 2026

- **Identity change** — Plugin identity changed from Store Insights with AI Lite to Store Insights for WooCommerce. Change made to comply with woocommerce and wp branding guideline.

### Security
- Removed the bundled `plugin-update-checker` library, the Composer autoloader, and the GitHub update-check hook. Updates now come from WordPress.org only, and the plugin makes no request to `api.github.com`.
- The API key is no longer passed to the browser through `wp_localize_script`. Only a `hasApiKey` boolean is exposed.
- Added `uninstall.php`; deactivating the plugin no longer deletes the settings or the insight history.
- Added suggested privacy policy text via `wp_add_privacy_policy_content()`.
- SQL validator: table aliases are now collected from declared `FROM`/`JOIN` aliases instead of accepting any 1–4 character token as a table name.
- SQL execution: a `LIMIT 200` clause is appended before the query runs, so unbounded queries no longer load every row into memory. The schema lookup now uses `$wpdb->prepare( 'SHOW COLUMNS FROM %i', … )`.
- Capability checks are consistent (`manage_woocommerce`) across the menu page, the AJAX endpoints, and the settings handlers.

### Fixed
- The Max Tokens setting takes effect again (`build_request_body()` had a hardcoded `16000`).
- API request timeout reduced from 600s to 90s so it no longer exceeds `max_execution_time` on shared hosts.

### Removed
- Debug `error_log()` calls that wrote the system prompt, user prompt, and the full API response to the PHP error log.
- Dead code: `handle_regen_insight()`, `ALLOWED_FUNCTIONS`, a duplicated `return`, and the unused `assets/js/chart.asset.php`.
- Regulatory compliance claims from `readme.txt` and `README.md`, replaced with factual data-flow wording.
- Bundled `vendor/`, `composer.json`, `composer.lock`, and the `Screenshots` section of the readme.

### Added
- `.distignore` and `npm run dist` for building the WordPress.org distribution folder.
